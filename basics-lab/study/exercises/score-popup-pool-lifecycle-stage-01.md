# 第 11 关加速包：得分飘字的对象复用与回收边界

本关继续使用 `basics-lab` 的 `Hello` 场景、`PopupLayer` 与 `ScorePopup` Prefab；不新建场景，不改变 Inspector 中已有的两个绑定。

你的节奏目标仍是普通关卡约三倍的知识量。本包由 3 个极短的预测检查和 1 个完整实现组成；前三项用于建立概念，不单独计为通过。

## 已验证的前置知识

- `@property(Prefab)`、`instantiate` 和 `@property(Node)` 绑定。
- PopupLayer 的本地坐标、子节点 Label、`UIOpacity`。
- Tween 的上移、淡出和完成回调。
- 连续点击产生多个独立飘字实例。

## 本关的新概念

1. **物理节点与逻辑效果的生命周期不同。** 上一关的一次效果是“创建 → 播放 → 销毁”。本关的一次效果改为“取得 → 播放 → 回收”；节点本身可以在多次效果之间继续存在。
2. **空闲池是所有权集合。** 只有已经回收、当前未展示的节点才能进入空闲集合；取出后必须立刻不再属于空闲集合。
3. **复用前必须重置可变状态。** 上一次效果留下的位置 `y=80`、透明度 `0`、文字或 Tween 都不能泄漏到下一次效果。
4. **Tween 的停止目标是精确对象。** `tween(tmpPopup)` 的目标是节点，`tween(opacity)` 的目标是 `UIOpacity` 组件。停止时也必须分别传入相同对象，例如 `Tween.stopAllByTarget(target)`。
5. **旧回调可能晚到。** 节点被回收、又很快再次取得时，旧 Tween 的完成回调若仍执行，可能把“新的效果”提前回收到池里。因此在取得和回收边界都要处理仍挂在该对象上的 Tween。
6. **回收必须幂等。** 同一节点重复回收不能在空闲集合中出现两份；否则随后两次取得会同时拿到同一个节点。

## 微检查（先用自己的话回答，再写代码）

## 集成练习

只修改 `basics-lab/assets/scripts/Welcome.ts` 的“飘字”区域及必要 import，把当前“每次 `instantiate`，结束时 `destroy`”改为手写对象复用池。

实现约束：

1. 在组件中保存一个空闲 `Node` 集合（数组或 `Set` 均可）。它只存放已回收飘字。
2. 把“取得飘字”和“回收飘字”抽成职责清晰的私有方法；`genScorePopup` 只负责协调一次效果。
3. 取得时：优先拿走一个空闲节点；集合为空才 `instantiate(this.scorePopupPrefab)`。确保节点位于 `popupLayer` 下并处于激活状态。
4. 每次取得后、启动 Tween 前，完整重置本次效果所依赖的状态：本地位置 `(0, 0, 0)`、Label 正负文本、`UIOpacity` 为 `255`，以及任何遗留 Tween。
5. 上移与淡出完成后回收同一个节点。正常效果结束不得 `destroy()` 该飘字节点；回收应让它不再显示，并重新加入空闲集合。
6. 在取得与回收的边界，停止以飘字节点和 `UIOpacity` 组件为目标的旧 Tween。为此需要从 `cc` 导入 `Tween`。
7. 回收方法必须防重复：无论旧回调、重复调用还是其他路径触发，空闲集合不能保存同一节点两次。
8. 不修改既有得分下限、按钮/键盘输入、回合状态机、`PopupLayer` 或 Inspector 中的 Prefab 绑定。

## 验收

1. 首次点击加/减分仍显示正确的 `+1` / `-1` 飘字；不可再减分时不生成飘字。
2. 等一个飘字结束后再次点击：它从 `(0, 0, 0)`、完全不透明状态重新开始，而非从高处或半透明状态出现。
3. 快速连续点击至少 10 次：活跃飘字可同时存在，结束后都消失；之后再次点击不出现提前消失、位置跳变或闪烁。
4. 运行静态检查：

```sh
python3 study/auditors/score_popup_pool_lifecycle_stage_01.py --script assets/scripts/Welcome.ts
```

## 不在本关范围

- Cocos 的通用 `NodePool` 或全局对象池服务。
- 预热数量、容量上限、跨场景缓存与异步资源加载。
- 将对象池抽成独立通用框架。
