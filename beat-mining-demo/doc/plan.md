# Beat Mining Demo 第一轮玩法与手感打磨计划

- 编写日期：2026-09-17
- 目标项目：`beat-mining-demo`
- Cocos Creator 版本：3.8.8
- 入口场景：`assets/scenes/Game.scene`
- 文档用途：供后续开发 Agent 直接实施、验证和交付

## 1. 开发目标

本轮只打磨现有单关的玩法、用户体验和操作手感，不扩展背包、商店、剧情、敌人、随机地图、关卡选择或平台功能。

需要解决以下问题：

1. 玩家节拍按准但没有矿石目标时，当前逻辑仍会判定 Miss、清空连击并计入统计，容易让移动阶段产生不合理惩罚。
2. 玩家在矿石边缘挥镐时，视觉距离与有效攻击范围可能不一致，需要提供轻量的位置辅助。
3. 当前四拍指示主要展示已经到来的拍点，玩家缺少对下一拍的连续预判信息。
4. 游玩 HUD 同时展示大量调试统计，核心信息层级不够清晰。
5. Perfect 连击目前主要改变视觉脉冲，没有直接影响挖矿收益或效率。
6. 结算只罗列原始数据，缺少明确评级和下一次重玩的目标。

完成后，玩家应能更容易判断何时挥镐、是否进入攻击范围、为什么没有造成伤害，并能从 Perfect 连击和结算结果中获得明确的继续挑战动力。

## 3. 具体开发要求

### 3.1 将“无目标空挥”和节奏 Miss 分离

当前行为中，玩家即使准确命中拍点，只要没有矿石处于有效范围，也会被改判为 Miss。需要将空间状态与节奏判定分开。

要求：

1. 只有玩家存在可攻击目标时，挥镐才进入 Perfect、Good、Miss 的正式统计。
2. 没有目标或目标不在可辅助范围内时：
   - 允许播放轻量空挥动画和挥镐音效；
   - 显示中文提示 `距离不足`；
   - 可以附带 EARLY/LATE 信息，但不得显示为正式 Perfect、Good 或 Miss；
   - 不增加 Perfect、Good、Miss 数量；
   - 不改变最大连击；
   - 不清空当前连击和 Perfect streak；
   - 不计入平均节拍偏差；
   - 不消耗当前节拍槽，玩家在同一拍进入范围后仍可进行一次正式判定。
3. 玩家朝向相反且身后存在最近矿石时，提示 `请面向矿石`，处理规则与 `距离不足` 相同。
4. 正式 Miss 仍然清空 combo 和 Perfect streak。
5. `TOO FAST` 规则保持不变，但只能由已经发生过正式判定的节拍槽触发。
6. 关卡计时从第一次对有效目标进行正式判定时开始，空挥不得启动计时。

建议在 `BeatManager` 中增加“只预览、不消费节拍槽”的判定能力，或先完成目标检测，再调用会消费节拍槽的正式判定。不得通过判定后回滚计数来模拟该行为。

### 3.2 增加矿石边缘攻击辅助

现有正式攻击范围约为玩家挖掘点与矿石中心距离 92 像素。保留原始范围，并在范围外增加最多 24 像素的辅助带。

要求：

1. 目标必须位于玩家当前朝向。
2. 目标位于原始范围内时，保持现有行为。
3. 目标位于原始范围外、但进入辅助带时：
   - 按下空格后将玩家沿水平方向平滑移动到原始有效范围内；
   - 单次辅助移动不得超过 24 像素；该上限于 2026-09-18 确认调整，用于完整覆盖 24 像素辅助带，确保玩家处于辅助带最外缘时也能移动进入原始 92 像素攻击范围；
   - 辅助移动时长控制在 60～90 ms；
   - 镐头接触目标时再造成伤害，保持现有“输入立即判定、接触时结算伤害”的结构；
   - 不允许穿过矿石或移动到场景边界之外。
4. 目标超过辅助带时按 3.1 的 `距离不足` 处理。
5. 矿石进入原始范围时使用现有青色边框；进入辅助带但未进入原始范围时，使用更暗的青色虚弱提示或低亮度边框，不能与正式可挖状态完全相同。
6. 辅助移动不得影响玩家正常的加速、减速和朝向控制；动画结束后速度需要处于可预期状态，不能产生突然滑行。

### 3.3 增加下一拍的连续视觉预告

保留顶部四拍方块，在其基础上增加连续蓄力表现，不新增大型节奏轨道。

要求：

1. 当前即将到来的拍点方块，在一个拍长内从约 85% 缩放逐渐增长到 115%。
2. 颜色从暗色平滑过渡到黄色，拍点到达时短暂闪亮，然后恢复。
3. 每小节第 1 拍应比其余三拍更明显，但不能遮挡判定文字。
4. 音乐未开始、暂停校准或设置窗口打开时，预告动画停止并恢复静态状态。
5. 预告必须由 `BeatManager` 的实际音乐时钟驱动，不得另建一个独立计时器。
6. 低连击时保持克制；Perfect streak 增长后可以适当增强拍点闪光，但不得持续放大整个 HUD。

### 3.4 精简游玩 HUD，保留结算统计

游玩阶段的第一视觉层级应是拍点、判定、目标矿石和角色。

要求：

1. 游玩中始终保留：
   - `COMBO`；
   - 矿石数量；
   - 矿脉进度；
   - 四拍预告；
   - 当前 Perfect、Good、Miss、距离不足或朝向错误反馈。
2. EARLY/LATE 毫秒数在每次正式判定后显示，并在约 700 ms 后弱化或隐藏。
3. `P/G/M/MAX/AVG` 不再长期显示在游玩底部，完整数据仅在结算时展示。
4. `OFFSET` 从主 HUD 移除，仅在设置和校准界面显示。
5. 底部操作提示在首次有效命中后逐渐淡出；玩家打开设置后可以再次看到快捷键提示。
6. 不删除内部统计字段和现有调试状态接口，浏览器验证仍需读取这些数据。

### 3.5 让 Perfect streak 提供实际收益

本轮采用简单、容易理解的增伤规则，不新增能量条。

要求：

1. 连续 Perfect 达到 3 次后进入 `热手` 状态。
2. `热手` 状态下：
   - Perfect 基础伤害由 2 提升到 3；
   - Good 仍造成 1 点伤害；
   - 矿石碎屑数量、命中特效和命中音效允许适度增强。
3. Good 会结束 Perfect streak 和 `热手`，但保留普通 combo。
4. Miss 会同时清空 combo、Perfect streak 和 `热手`。
5. 距离不足、朝向错误和同拍重复输入不得结束 `热手`。
6. 进入 `热手` 时显示一次短提示；之后通过 COMBO 颜色或角色/镐头的轻量高亮持续表达状态，不能一直占用中央判定区域。
7. 调整后必须确认六块矿石仍能形成逐步增强的节奏，不得让最终水晶在一次命中后直接破碎。必要时可以小幅调整矿石 HP，但不得修改矿石数量和掉落数量。

### 3.6 完善单关结算和重玩目标

全部矿石破坏且所有掉落收集完成后，显示结构化结算。

要求：

1. 结算展示：
   - 通关用时；
   - Perfect、Good、Miss 次数；
   - 最大 combo；
   - 平均绝对节拍偏差；
   - 节奏准确率；
   - S/A/B/C 评级。
2. 准确率只统计正式判定：Perfect 计 100 分，Good 计 60 分，Miss 计 0 分，再除以正式判定次数。空挥、距离不足、朝向错误和 `TOO FAST` 不进入分母。
3. 评级规则：
   - S：准确率不低于 90%，且 Miss 为 0；
   - A：准确率不低于 80%；
   - B：准确率不低于 65%；
   - C：其余结果。
4. 根据本次数据显示一条下一局目标：
   - 存在 Miss：提示减少 Miss；
   - 没有 Miss 但准确率低于 90%：提示提高 Perfect 比例；
   - 已达到 S：提示挑战更低用时或更高最大连击。
5. 保留 `R` 重新试玩，并在结算中清楚展示。
6. 重开后所有本局统计、热手状态、矿石、掉落、HUD 和计时必须完全重置；玩家输入补偿值保持不变。

## 4. 交互优先级

实现时按以下顺序处理，避免 UI 表现掩盖规则错误：

1. 无目标空挥与正式判定分离。
2. 矿石边缘攻击辅助。
3. Perfect streak 的热手收益。
4. 下一拍视觉预告。
5. HUD 精简。
6. 结算评级和下一局目标。

每完成一项，都应先验证核心行为，再继续下一项。

## 5. 验收场景

必须使用 Cocos Creator 3.8.8 构建 Web Desktop，并通过真实浏览器键盘操作验证。仅 TypeScript 编译通过或页面成功加载不算完成。

至少覆盖以下场景：

1. 在没有目标的位置准确按拍挥镐：显示 `距离不足`，combo、streak 和 P/G/M 不变化。
2. 背对矿石准确按拍挥镐：显示 `请面向矿石`，不消费该节拍槽；立即转向后，同一拍仍能正式判定。
3. 在辅助带内挥镐：玩家平滑靠近，判定立即显示，伤害在镐头接触时发生。
4. 超过辅助带挥镐：不吸附、不造成伤害、不重置连击。
5. 连续三个 Perfect：第三次后进入热手，后续 Perfect 造成 3 点伤害。
6. 热手期间得到 Good：combo 增加或保持正常连续，Perfect streak 和热手结束。
7. 热手期间 Miss：combo、Perfect streak 和热手全部清空。
8. 同一拍连续按空格：正式判定后重复输入显示 `TOO FAST`，不产生第二次伤害。
9. 顶部拍点预告与 BGM 保持同步；运行多个音乐循环后不得出现肉眼可见漂移。
10. 打开设置或进入输入校准：玩法输入被正确阻止，节拍预告停止，退出后 BGM 与判定重新同步。
11. 完整通关：结算数据、准确率和评级符合规则，全部矿石和矿石掉落收集完之前不得提前结算。
12. 按 R 重开：关卡状态完全恢复，输入补偿值仍保留。
13. 浏览器控制台无新增 error 或 warning。
